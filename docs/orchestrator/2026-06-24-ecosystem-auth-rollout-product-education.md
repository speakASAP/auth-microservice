## Auth Contract Baseline

Static source reviewed in `auth-microservice`:

- `docs/UNIFIED_AUTH_CONTRACT.md` defines Auth-hosted entry points `GET /login` and `GET /register` at `https://auth.alfares.cz`, with `return_url`, optional `client_id`, and optional `state`.
- The hosted handoff redirects back to the consumer `return_url` with fragment fields including `access_token`, `refresh_token`, `expires_at`, `state`, and `auth_method` for OAuth/magic-link style flows.
- `POST /auth/login` accepts `{ identifier, password }` for email or phone and legacy `{ email, password }`.
- `POST /auth/register-contact` is provisioning-only and must not be treated as authentication.
- `POST /auth/validate` remains the default consumer token validation pattern.
- `docs/CONSUMER_JWT_VALIDATION_STANDARD.md` classifies `shop-assistant`, `speakasap/api-gateway`, and `school-committee` as default `POST /auth/validate` consumers; consumers must not mint Auth JWTs locally or validate Auth user tokens with service-owned signing secrets.
